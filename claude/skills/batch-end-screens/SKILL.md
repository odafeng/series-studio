# 批次加片尾

## 為什麼是瀏覽器不是程式

YouTube Data API 沒有片尾與資訊卡的端點。`videos.update` 只能改標題、描述、標籤、縮圖。
片尾只存在於 Studio 編輯器裡，沒有公開介面，也沒有官方批次工具。

這落在「路徑不穩定、目標確定」那一格：要做的事很明確（每支加一個播放清單元素），
但 Studio 的 DOM 會改、載入時間不可預測。所以用瀏覽器 agent，理由是環境不穩定。

## 前置

- Chrome 已登入擁有該頻道的 Google 帳號（不是個人帳號——先確認登入的是頻道擁有者）
- 手上有：影片 ID 清單、目標播放清單名稱
- Shorts 不支援片尾，清單裡要先排除
- 影片長度須 ≥ 25 秒

## 每支影片的操作序列

新版 Studio 把片尾合併進了影片編輯器的時間軸，入口是 `片尾` 那一列。

```
https://studio.youtube.com/video/<VIDEO_ID>/editor
  → 片尾 列的 [+]
  → 播放清單
  → 點目標播放清單卡片
  → （若回到「影片編輯器」）片尾 列的 [編輯]
  → 儲存
```

第一次進編輯器會有「在時間軸上編輯及套用影片元素」的導覽頁，按一次「開始使用」，之後不再出現。

元素的時間範圍**不用手動拖**：加入後自動落在最後 20 秒（例如 7:13 的片會是 `6:52.16 → 7:12.16`），
正好符合 YouTube 片尾必須在最後 5–20 秒的規定。

## 兩條吃過虧的規則

### 1. 一個 browser_batch 只能有一個「開浮層」的點擊

點 `[+]` 打開選單後，**同一個 batch 裡接著點選單項目不會生效**——即使中間 wait 9 秒也一樣。
一開始以為是等太短，把 3 秒加到 6 秒、9 秒，全都沒用。假設推翻了：不是時間問題。

實際規律是：開啟浮層（選單、對話框）的那一下必須是 batch 的最後一個動作，
點浮層內容要放到下一次工具呼叫。對話框裡打字同理。

所以每支影片大約需要 5 到 7 次呼叫，不要試圖壓成一次。

### 2. 每一步都要截圖確認，不要盲目往下點

Studio 的載入時間在 15 到 40 秒之間跳動，同一個座標在不同時刻可能是 `[+]`、可能是 `[編輯]`、
也可能什麼都不是。頁面出現水平捲軸時整個左欄會位移約 15px，寫死的座標就會偏掉。

盲點會很貴：曾經有一次連續點擊把已加好的元素**復原**掉了（`復原` 變灰、`重做` 變亮就是這個狀態）。
按 `重做` 救不回完整狀態，只會回到範本選擇畫面，最後只能重新載入頁面從頭做一次。

## 驗收

重新載入編輯器，`片尾` 那一列顯示 `編輯` 而不是 `+`，且 `復原`／`重做` 都是灰的，代表存檔成功。

資料端要等流量累積：

```bash
sqlite3 <db> "SELECT source_type, SUM(views) FROM video_traffic WHERE source_type='END_SCREEN' GROUP BY 1;"
```

加完後第 7 天與第 28 天各查一次。有數字就代表路通了。

## 另一條路：從影片匯入

`片尾 [+] → 套用範本 → 從影片匯入 → 搜尋影片 → 選片`，會複製那支影片的整組片尾版型，
時間範圍自動對齊到目標影片的長度。

版型複雜（多個元素、特定位置）時值得用。只加一個播放清單元素的話，
直接走 `播放清單` 反而少兩層對話框。
